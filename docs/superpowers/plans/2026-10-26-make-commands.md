# Make-команды для локального стенда

**Goal:** быстро управлять Java-сервисами и UI; полный запуск гарантирует готовность Docker-зависимостей.

**Architecture:** Makefile — короткие команды; `scripts/service.sh` — общая логика PID,
портов, ожидания готовности, сборки и перезапуска. Старые stop/status используют тот же код.
Новые зависимости и системный автозапуск не добавляются. Работа локальная, прямо запрошена
владельцем; Git в этой папке не инициализирован, поэтому без worktree и коммитов.

## Ограничения

- `make up` / `make start` сначала выполняют `docker compose up -d --wait` через `infra-up`.
  Остальные команды управляют только приложениями; штатный lifecycle не удаляет volumes.
- Сборка выполняется до остановки. Если сборка не прошла, работающий сервис остаётся запущенным.
- Останавливаем только PID своего JAR/Vite. Чужой PID, занятый порт или запуск из IDE — явная ошибка.
- Java 21, Gradle Wrapper, Bash macOS, Node; UI остаётся Vite dev server с HMR и strictPort.
- Сборка использует обычный Gradle. Отдельных профилей и режимов запуска нет;
  без пересборки стартуют существующие JAR.

## Review focus

PID reuse, порт занят не нашим процессом, failed build, неверное имя сервиса,
разные lifecycle Docker/Java/UI. Все эти условия покрываются тестами ниже.

## Выполнено и проверено

Первоначальная проверка: 13 lifecycle-тестов GREEN, Gradle test и два frontend API-теста GREEN.
Внешние JVM/сеть/сборка в lifecycle-тестах заменены, PID и сигналы настоящие, проекты изолированы.
Ревью обнаружило слишком широкое совпадение пути JAR: две проверки jar.old/пути в аргументе
сначала RED, после проверки полного launch suffix и UID — GREEN. На macOS временный путь
в тесте канонизирован (`/var` и `/private/var`), чтобы тест действительно проверял эту ошибку.

До очистки Docker проверены up, restart-payment, restart-ui и оба варианта rebuild.
Все четыре приложения были UP. Повторный up сохранил PID.
У Audit PID остался прежним при одиночных рестартах соседей.
Docker IDs и StartedAt всех трёх контейнеров до/после совпали.

Ограничение: конкурентные конфликтующие lifecycle-команды не сериализуются глобальным lock;
для простого локального стенда команды выполняются последовательно, как указано в памятке.
После уточнения владельца `scripts/start.sh` упрощён до build → up без аргументов.
Проверки дополнены до 20: инфраструктура поднимается перед приложениями, ошибки Docker и Compose
не разрешают запуск Java, удалённые аргументы отвергаются. Все 20 тестов прошли.
Полные `make test` и `make build` прошли без специальных режимов. Бизнес-код не менялся.
