# Payment Platform: консоль платежей и HTTP API

**Не согласованный черновик агента.** Лимиты Antifraud, точный жизненный цикл и переименование
служебных маршрутов ниже — предложения, не решения владельца. Внедрение остановлено
до явного согласования подробного плана.

Источник: запрос владельца 26.10.2026 и приложенный «вопросы к демонстрации как ее проводить».
Владелец попросил предложить план и затем внедрить, без отдельной остановки на выборе процесса.

## Цель

Показывать один реальный платёж от HTTP-запроса до статуса и сохранённой истории Audit.
UI — окно наблюдения и Swagger, не самостоятельный тренажёр по технологиям.

## Решение

- Три экрана: «Обзор», «Платежи», «API». Lab и его интерфейс удаляются.
- Обзор: Payment :8081, Antifraud :8082, Audit :8083, доступность и текущие настройки;
  последние платежи. Подробности сервиса доступны по нажатию.
- Полный список платежей без прежнего жёсткого ограничения 20; UI разбивает его на страницы.
- Карточка: сумма, владелец, тип, статус, причина решения и история из БД Audit.
  Технические параметры не занимают основной экран.
- API: раскрывается Swagger одного сервиса. Документация генерируется из настоящих контроллеров
  через springdoc; встроенная страница того же backend отправляет запросы в свой origin.
  Не пишем второй собственный Swagger и не подменяем ответы.
- Типы: CARD, QR, INSTALLMENT, RECURRENT. Отсутствующий тип означает CARD для совместимости.
- Предсказуемые учебные лимиты Antifraud: CARD — 100000 RUB, QR — 50000 RUB,
  INSTALLMENT — 30000 RUB, RECURRENT — 10000 RUB. Равенство лимиту разрешено.
  HTTP 503/timeout — технический сбой, не бизнес-отказ. Отклонённые платежи сохраняются.
- Статусы остаются NEW, CONFIRMED, REJECTED. Нет таймеров, изображающих реальную обработку.
  Создание возвращает NEW либо REJECTED; отдельное подтверждение NEW → CONFIRMED.
- Kafka передаёт PaymentCreated, PaymentRejected и PaymentConfirmed в payment.events.
  Только commit разрешает публикацию. Audit хранит eventId, тип платежа, статус и причину.
  Повтор последнего события сохраняет eventId; UNIQUE(event_id) исключает повторный эффект.
- Административные настройки демонстрации доступны в Swagger как admin HTTP endpoints,
  не как отдельный Lab. Старые внутренние скрипты обновляются на новые маршруты.
- contracts переименовывается в common-libs (Common Libs), Java package school.sorokin.commonlibs.
- Данные сохраняются. Добавляются совместимые поля с defaults; актуальные имена таблиц
  приведены к виду без префикса. Старые Kafka topics остаются нетронутыми. Outbox не добавляется.
- Лимиты памяти контейнеров: PostgreSQL 512 MiB, Redis 192 MiB, Kafka 1 GiB с heap 512 MiB.
  Это ограничения ресурсов; данные по-прежнему на дисковых Docker volumes, не в RAM.

## Рассмотренные варианты

Собственный HTTP-клиент потребовал бы дублировать OpenAPI и редактор запросов; не нужен.
Три одновременно раскрытых Swagger перегрузили бы страницу; показываем один за раз.
Автоматический процессинг добавил бы очередь/планировщик и искусственные задержки;
при проверке понятнее управлять реальными переходами отдельными HTTP-запросами.

## Проверка

Тесты правил по типам, переходов и commit-событий, фильтра аудита и идемпотентности;
сборка и прежние lifecycle-тесты; реальные Swagger JSON и запросы всех трёх сервисов;
интеграционные сценарии; визуальная проверка встроенным браузером.
