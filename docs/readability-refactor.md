# Читаемый код и компактный UI

> Архив первоначального рефакторинга. Текущий порядок показа — в scenarios.md.

Запрос владельца от 25 октября 2026. Референс:
`Mini Payment System`.

## Принятый подход

Сохраняем демонстрационные сценарии, данные и JSON-контракты. Приводим код к структуре старого
проекта: `api`, `api/dto`, `api/errors`, `domain`, `domain/db`, `config`, `kafka`.
HTTP-клиент, кэш и учебные переключатели имеют отдельные пакеты `client`, `cache`, `lab`.

DTO — отдельные record-классы с осмысленными именами и комментариями к каждому компоненту.
Entity — закрытые поля, Lombok getters и явные конструкторы. Mapper отделён от Entity.
У каждого бина короткое пояснение роли; конструкторы и вызовы с несколькими аргументами
разбиты на читаемые строки. Класс запуска Antifraud содержит только запуск приложения.

Сборка: Gradle Kotlin DSL + Wrapper, Java 21. Runtime Spring Boot 3.5.3 сохраняется.
Настройки: `application.yml`, включая лимиты HTTP, retry и названия Kafka-топиков.
Старые POM/properties заменяются после резервного копирования и проверки Gradle.

## UI

Основной экран: три сервиса, платежи и короткая лента. Технические счётчики, SQL, порты,
UUID, ключ кэша и настройки открываются в карточках и раскрывающихся блоках.
Сохраняем тёмную тему и зелёный акцент. Убираем дублирующую навигацию, декоративные панели
и постоянно раскрытый диагностический текст.

## Проверка

- Сборка и unit-тесты через `./gradlew build`.
- Те же 13 integration-сценариев через `node scripts/smoke.mjs`.
- Frontend build, затем браузер: обзор → карточка → подробности, события, лаборатории.
- Запуск из `build/libs`, без Maven.

Резервная копия: `.runtime/backups/2026-10-25-before-readable-refactor.tar.gz`.

## Результат

Сборка переведена на Gradle, POM удалены; `application.properties` заменены на YAML.
Исходный Mini Payment System не изменялся. DTO, entity, mapper, API и бизнес-сервисы
разделены; Antifraud больше не совмещает запуск, HTTP API и бизнес-логику в одном классе.
Все существующие учебные режимы и JSON-контракты сохранены.

Главный экран упрощён; сервис, платёж, событие и долговечная запись Audit открывают
отдельные карточки. Код и SQL лабораторий по умолчанию свёрнуты. Подробные показатели
и снимок состояния доступны через «Диагностику». Frontend и JS-скрипты отформатированы.

Фактические результаты и ограничения проверки — в [verification.md](verification.md).
