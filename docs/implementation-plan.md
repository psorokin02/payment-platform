# Payment Platform — план реализации

Основа: [план владельца в Buildin](https://buildin.ai/16ba995e-a479-4b25-8bfc-07856820df8e),
обновлённый 28 октября 2026. Локальный учебный проект, без реальных платежей.

## Решение

Три Java 21 / Spring Boot 3.5 сервиса: Payment, Antifraud, Audit. PostgreSQL — источник данных,
Redis — кэш карточки, Kafka — транспорт событий. React/TypeScript — консоль оператора.
Статусы и события приходят с backend, SQL виден в обычных логах Hibernate. Подготовленные неисправные режимы
явно подписаны. Основной показ переключается через API без смены Git-ветки и пересборки.

Выбрана настоящая локальная система вместо UI-макета с имитацией транспорта. Docker поднимает
только зависимости; Java-процессы запускаются из собранных JAR и доступны для открытия в IDE.
Это удобнее полного Docker build при небольших изменениях демонстрационного кода.

## Задачи и проверки

- [x] Инфраструктура и контракты: Gradle-модули, Compose, health-check; проверить сборку.
- [x] Payment: создание, чтение, подтверждение, lazy owner и fetch join; интеграционно проверить
  реальные N+1 SQL и исправление. Невалидная сумма, отсутствующий ID и повтор confirm — явные ответы.
- [x] Redis: miss/hit, подготовленный stale-режим, удаление после commit; проверить read/change/read.
  Отказ Redis даёт fallback в PostgreSQL с явным событием.
- [x] HTTP: контролируемый Antifraud, timeout, ограниченный retry, circuit breaker; проверить
  временные ошибки, исчерпание попыток и business reject без бессмысленного retry.
- [x] Kafka: события платежей, пауза consumer и persistent idempotency;
  проверить отложенный аудит и duplicate eventId. Позднее retry/backoff/DLT удалены.
- [x] UI: обзор с созданием, список платежей и карточка слева, отдельные Сервисы, Swagger и Аудит.
  Настройки применяются по кнопке, логи каждого сервиса доступны без IDE.
- [x] Запуск: start/stop/status, smoke-тест API, сквозной сценарий; проверить всё на реальной
  PostgreSQL/Redis/Kafka. Исходные данные детерминированы и не содержат персональных сведений.

## Границы

Outbox/Saga, настоящий процессинг, авторизация, Kubernetes и production-деплой не реализуются.
Известное окно между commit в БД и публикацией Kafka-события документируется.
Варианты блокировок платежей удалены.
HTTP retry/breaker сохранены в резерве. Последующим решением 29 октября владелец удалил
Kafka retry/DLT и имитацию ошибок Audit; актуальные проверки — в simple-service-flow.md.
Для переключения используются варианты методов и runtime-настройки, не Git-ветки.
