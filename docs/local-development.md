# Как работать с Payment Platform

Все команды выполняются из корня проекта:

```bash
cd <project-root>
make help
```

## Главное различие

**Docker** держит PostgreSQL, Redis и Kafka. **Java-сервисы и UI** — отдельные локальные
процессы, не Docker-контейнеры. Поэтому Docker может быть полностью зелёным, а веб-страница
не открываться. `make status` показывает эти два слоя отдельно.

`make up` сначала поднимает PostgreSQL, Redis и Kafka через Docker Compose и ждёт их готовности,
затем запускает Java и UI. `make infra-up` запускает только инфраструктуру. Одиночные команды,
а также `restart` и `rebuild`, управляют только приложениями. Данные хранятся в обычных
Docker volumes; эти команды их не удаляют. Дополнительных профилей нет.

## Память

Лимиты включены в обычную конфигурацию проекта и применяются при `make up` / `make restart`:

| Компонент | Лимит |
|---|---|
| Kafka | Контейнер 512 МиБ; Java heap 128–256 МиБ; health check heap до 64 МиБ |
| PostgreSQL | Контейнер 256 МиБ; shared buffers 64 МиБ, work memory 2 МиБ, maintenance 32 МиБ, до 40 соединений |
| Redis | Контейнер 128 МиБ; данные до 64 МиБ, политика `noeviction` |
| Каждый backend, запущенный через Make | Java heap 32–192 МиБ |
| Vite и frontend build через Make | V8 old space до 256 МиБ |
| Gradle | Heap до 384 МиБ; один worker; CLI daemon завершается после команды, IDEA daemon — после минуты простоя |
| Java-тесты | Heap до 256 МиБ; один fork |

Heap не равен всей памяти процесса: JVM также использует metaspace, стеки и служебные буферы.
У Docker-контейнеров задан жёсткий лимит памяти без дополнительного swap. При заполнении Redis
новые записи кэша могут возвращать ошибку; приложение продолжает читать данные из PostgreSQL.

Изменил `compose.yaml` → выполни `make infra-up`: Compose пересоздаст нужные контейнеры,
сохранив volumes. Изменил параметры heap в `scripts/service.sh` → `make restart`.
Запуск backend напрямую из IDEA обходится без Make: укажи `-Xms32m -Xmx192m` в VM options
его Run Configuration.

Отдельно на Mac владельца согласованы Docker Desktop VM 2 ГиБ и IntelliJ IDEA heap 1536 МиБ.
Это настройки приложений на компьютере, а не часть Compose; IDEA и Docker требуют перезапуска
для изменения этих лимитов. Если понадобится запуск других больших Docker-проектов,
общий бюджет VM нужно будет пересмотреть.

## Шпаргалка

| Что нужно | Команда |
|---|---|
| Поднять инфраструктуру, затем Java + UI из существующих сборок | `make up` |
| Поднять только PostgreSQL, Redis и Kafka | `make infra-up` |
| Поднять только Payment / Antifraud / Audit | `make payment` / `make antifraud` / `make audit` |
| Поднять только frontend | `make ui` |
| Перезапустить Payment без пересборки | `make restart-payment` |
| Пересобрать Payment и перезапустить только его | `make rebuild-payment` |
| Перезапустить frontend | `make restart-ui` |
| Пересобрать и перезапустить Java + UI | `make rebuild` |
| Перезапустить Java + UI без сборки | `make restart` |
| Только собрать всё, ничего не останавливать | `make build` |
| Только собрать один модуль / UI | `make build-payment` / `make build-ui` |
| Остановить один сервис / UI | `make stop-payment` / `make stop-ui` |
| Остановить Java + UI, оставить Docker | `make stop` |
| Посмотреть состояние | `make status` / `make status-payment` |
| Читать логи одного сервиса / всех | `make logs-payment` / `make logs` |

В командах с суффиксом `payment` его можно заменить на `antifraud`, `audit`, `ui`.
Есть и полная форма запуска: `make start-payment`, `make start-ui`.

## Обычный рабочий день

1. Запусти Docker Desktop → `make up`. Контейнеры поднимутся автоматически.
2. Изменил Java-код Payment → `make rebuild-payment`.
3. Изменил только настройки `application.yml` → тоже `make rebuild-payment`: YAML упакован в JAR.
4. Изменил общий модуль `common-libs` (Common Libs) → `make rebuild`, чтобы все три JAR получили обновление.
5. Изменил React/CSS → просто сохрани файл: Vite обновляет UI через HMR без рестарта.
6. Изменил `vite.config.ts`, зависимости или сам UI завис → `make restart-ui`.
7. Закончил → `make stop`. Docker и его данные останутся нетронутыми.

Если только что скачал проект и JAR ещё нет: сначала `make build`, затем `make up`.
Если frontend-зависимостей нет, `make build-ui` установит их через `npm ci` и проверит сборку.

## Что именно делают restart и rebuild

- `restart` использует уже собранный JAR. Изменённый Java-исходник в него сам не попадёт.
- `rebuild` сначала запускает Gradle build с тестами; для общего rebuild ещё проверяет frontend build.
  Только успешная сборка разрешает остановку и запуск. Ошибка сборки не гасит старые процессы.
- При отдельном rebuild Gradle собирает выбранный модуль и его зависимости. Соседние процессы не трогаются.
- UI всегда запускается как Vite dev server, даже после build. Production bundle нужен для проверки,
  а не для отключения HMR.
- Повторный `make up` или `make ui` не создаёт второй экземпляр уже управляемого процесса.

Перезапуск Java сбрасывает его учебные переключатели, счётчики и локальную ленту событий.
Данные PostgreSQL, Redis и Kafka при этом не удаляются. Открытую карточку платежа после
перезапуска лучше перечитать кнопкой «Прочитать снова».

## Логи, готовность и IDE

Логи лежат в `.runtime/payment-service.log`, `.runtime/antifraud-service.log`,
`.runtime/audit-service.log` и `.runtime/ui.log`. `make logs-*` показывает последние 80 строк
и продолжает следить за файлом. `Ctrl+C` выходит только из просмотра логов, не останавливая сервис.
После рестарта открой просмотр логов заново: лог текущего запуска записывается с начала.

Make дожидается HTTP health; для Audit — ещё и назначения Kafka partition. На это может
потребоваться некоторое время. Если сервис не поднялся, команда укажет нужный лог.
Живой PID сам по себе не означает готовность: например, Audit не готов без соединения с Kafka.
Если `make up` сообщает об ошибке скачивания образов или DNS, это проблема Docker-сети,
а не повод запускать Java без инфраструктуры.

Не запускай один и тот же сервис одновременно через IDE и Make. Если порт занят внешним
процессом или PID-файл указывает не на наш JAR/Vite, скрипт завершится с ошибкой и не станет
убивать чужой процесс. Сначала останови соответствующий Run в IDE.
Если сообщение явно говорит об устаревшем PID после перезапуска машины, проверь, что сервис
не слушает свой порт, и удали только его файл `.runtime/<service>.pid`; не удаляй данные БД.

Процессы запускаются в фоне через `nohup`; команда Make после готовности возвращает приглашение.
Это не системные службы: после перезагрузки Mac нужен новый `make up`.
Для самостоятельной работы запускай команды в своём Terminal, а не рассчитывай на срок жизни
временной сессии AI-агента.
Команды изменения состояния выполняй последовательно: дождись окончания `up`/`restart`/`rebuild`,
прежде чем запускать другую такую команду для тех же сервисов из соседнего терминала.

## Проверки

```bash
make test                         # тесты управляющих скриптов, Java и frontend
make test-scripts                  # только lifecycle, без настоящих JVM и Docker
make smoke                        # реальные API: создаёт учебные платежи, переключает режимы
make smoke-console                # Swagger, типы, сохранённый Antifraud, Audit и повтор события
```

UI: http://127.0.0.1:5173/. Payment :8081, Antifraud :8082, Audit :8083.

`./scripts/start.sh` — первоначальный запуск: выполняет `make build`, затем `make up`.
Аргументов у него нет. Для повседневной работы используй отдельные Make-команды.
