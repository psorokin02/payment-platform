Владелец согласовал экономные лимиты и перезапуск Docker Desktop / IntelliJ IDEA.
Все настройки обычные: отдельные RAM-профили, offline-режим и удаление данных не добавлялись.

## Настройки

| Компонент | Настройка |
|---|---|
| Docker Desktop VM | 2048 МиБ; Docker видит 2012721152 байта доступной памяти гостевой ОС |
| Kafka | Контейнер 512 МиБ, heap 128–256 МиБ; health-check heap 16–64 МиБ |
| PostgreSQL | Контейнер 256 МиБ; shared_buffers 64 МиБ; work_mem 2 МиБ; maintenance_work_mem 32 МиБ; max_connections 40 |
| Redis | Контейнер 128 МиБ; maxmemory 64 МиБ; noeviction |
| Каждый backend через Make | Heap 32–192 МиБ |
| Vite / frontend build через Make | V8 old space 256 МиБ |
| Gradle | Heap 384 МиБ; metaspace 256 МиБ; один worker; CLI daemon завершается после команды; IDEA daemon — после минуты простоя |
| Java-тесты | Heap 256 МиБ; один fork |
| IntelliJ IDEA | Heap 1536 МиБ; действующая JVM подтвердила MaxHeapSize=1610612736 |

Контейнеры не используют дополнительный swap сверх лимита памяти. Heap JVM/V8 не ограничивает
полную память процесса. Для запуска backend напрямую из IDEA нужны VM options
`-Xms32m -Xmx192m` в его Run Configuration; Make устанавливает их автоматически.

## Восстановление

Копии прежних конфигураций лежат в приватном каталоге
`.runtime/memory-limits-2026-10-29-before`. Каталог содержит настройки приложений; его не нужно
публиковать вместе с учебным проектом. Данные PostgreSQL/Redis/Kafka не удалялись.

Для изменения бюджета проекта редактируй `compose.yaml`, `scripts/service.sh`,
`gradle.properties` и лимит тестов в `build.gradle.kts`, затем используй `make infra-up`
и `make restart`. Изменение глобального бюджета Docker/IDEA требует их перезапуска.

Нет отдельного длительного нагрузочного тестирования, проверки умышленного OOM или ручного
браузерного прохода в этой задаче. Показанные сценарии и фактическая память проверяются отдельно;
успешная сборка сама по себе не доказывает отсутствие лагов всей системы macOS.

## Ограничение проверки IDEA

После первого запуска IDEA с подтверждённым heap 1536 МиБ занимала 3,1G по `vmmap`
вместо исходных 4,2G. В 12:08 она завершилась с нативным сбоем JVM:
`EXC_BAD_ACCESS / SIGABRT`, а не с явной `Java heap space`. Перед завершением лог отмечал
зависания UI. Crash report найден в стандартном каталоге DiagnosticReports; приватные
полные отчёты в учебный проект не копировались. Причина сбоя и связь с изменением heap
не установлены. IDEA запущена повторно: проект открылся, MaxHeapSize снова 1536 МиБ,
фактическая память около 3,2G. С открытой IDEA повторно прошли все 31 демосценарий.
Длительная устойчивость IDE требует отдельной проверки.
