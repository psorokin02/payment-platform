# Проверка Payment Platform · 29 октября 2026

Снимок до упрощения Kafka и удаления блокировок. Актуальная структура и проверки:
[упрощённый поток](simple-service-flow.md).

## Результат

- `make test`: 24 теста скриптов, 88 Java и 55 UI — всего 167, без ошибок.
- `make rebuild`: Java и UI собраны; все три сервиса и frontend перезапущены и готовы.
- Повторный полный `make smoke`: 13 технологических + 8 консольных + 6 feature + 4 Audit — 31 сценарий пройден на PostgreSQL, Redis и Kafka.
- Дополнительно восемь конкурентных HTTP-проверок одного requestId в настоящем Antifraud/PostgreSQL вернули одно сохранённое решение, без ошибок уникальности.
- N+1/JOIN: JPA-тест проверяет 13 и 1 prepared statements стандартной статистикой Hibernate. Live-проверка читает обычные SQL-логи; собственных SQL-счётчиков в API нет.
- Тесты покрывают разные причины HTTP-сбоя, 502 для ошибочного контракта без retry, конфликт параметров одного requestId и сохранность настроек при отказе очистки Redis.

Первый живой прогон остановился в проверке 21 платежа: один запрос в normal превысил 900мс.
В логах Antifraud начал обработку спустя примерно две секунды после отправки. Настройка таймаута
не менялась; полный повторный прогон завершился успешно. Первый журнал сохранён, а не перезаписан.

## Схема и данные

Audit использует одну текущую schema.sql без ALTER/backfill старых версий. Antifraud уже имел
одну начальную схему; Payment по-прежнему создаёт таблицы через Hibernate. Liquibase в проекте нет.
Пустая схема и её повторная инициализация проверены тестами на H2 PostgreSQL mode.
Отдельную пустую PostgreSQL-БД не создавали: существующая схема подходит. БД и volumes не удалялись;
интеграционные проверки добавили вымышленные платежи и события.

Финальное состояние: join/safe/timeout/optimistic, eventCopies=1, Antifraud normal,
Audit protection=true, consumer активен, failuresRemaining=0.

## Ревью и границы

Независимое source/diff-ревью: Critical/Important не найдено. Неблокирующий follow-up:
добавить отдельную проверку повторного сохранения настроек после восстановления Redis;
пока автотест проверяет первую половину — отказ не меняет настройки. Реализация повторной
попытки по ревью корректна; дополнительных изменений по этому замечанию не делали.

UI проверен сборкой и 55 автотестами; отдельного ручного браузерного прохода в этой итерации не было.
Отсутствие Outbox и гонки cache-aside остаются явно оговорёнными ограничениями учебного стенда.
Retry/breaker, Kafka retry/DLT и блокировки сохранены как резерв по выбору владельца.
